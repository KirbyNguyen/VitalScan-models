# VitalScan — Group 3: Biomarker Risk Prediction

Group 3's module for the AIT-500 VitalScan project. It takes biomarkers (heart rate, blood
pressure, …) plus profile data and predicts **diabetes** and **hypertension/heart-disease**
risk, then serves those scores over a REST API for the rest of the app to consume.

```
Group 1 (face scan) ─┐
                     ├─►  GROUP 3  ─► risk scores ─► instructor engine ─► Group 4 (explanation)
Group 4 / profile  ─┘   (this repo)
```

## The core idea: two models per condition

Every condition is trained two ways, because the features that make the *best* model aren't
the features the *deployed app* can actually collect:

| | Trained on | Use |
|---|---|---|
| **full_clinical** | every feature incl. lab tests (glucose, cholesterol, thallium scan…) | accuracy benchmark / evaluation only — the live app can't supply these |
| **deployable** | only what Group 1's scan + Group 4 profile provide (BP, heart rate, BMI, age…) | the model the app actually runs |

The gap between them is the honest finding the rubric's clinical-implications section asks for.

## Quickstart (clone & run)

**Requirements:** Python **3.11+** (developed/tested on 3.14), ~2 GB free disk for the venv.

```bash
git clone <your-repo-url> && cd VitalScan-models
bash setup.sh                                  # venv + deps + trains the served models (~2 min)
.venv/bin/uvicorn src.api:app --port 8000      # API at http://localhost:8000/docs
```

That's it — the **datasets are included** in the repo, so no downloads or Kaggle login needed.
`setup.sh` runs `src/train_compare.py`, which rebuilds the gitignored `models/` the API loads.

## The 14 models compared

LogReg · GaussianNB · KNN · SVM (RBF) · DecisionTree · RandomForest · ExtraTrees · AdaBoost ·
GradientBoosting · HistGradientBoosting · XGBoost · LightGBM · CatBoost · MLP (neural net).

Three families: simple/linear, tree-forests (bagging), and boosting — plus a neural net that
also covers the Task-5 stretch.

## Headline results

| Condition | Full-clinical | Deployable (served) | Passes rubric (>0.80)? |
|---|---|---|---|
| **Heart disease** | 0.91 (UCI, all features) | **0.875** (UCI, scan+profile) | ✅ |
| **Diabetes** | 0.82 (Pima, with glucose) | **0.808** (CDC, glucose-free) | ✅ |

The deployable diabetes model **trains on a different dataset by design**: glucose is Pima's
top feature but unmeasurable by a face scan, so the deployable model uses the **CDC/BRFSS**
dataset, which predicts diabetes from BP + BMI + lifestyle indicators with no glucose at all.

**Metrics in plain terms:** *ROC-AUC* = overall skill (0.5 random, 1.0 perfect, >0.80 good).
*Recall* = fraction of at-risk people we catch (rubric requires ≥0.80 — missing a sick person
is the dangerous error). *Precision* = fraction of our alarms that are real. We tune the
decision threshold to hit recall ≥ 0.80 and report the precision cost.

**Key findings**
1. Heart is deployable with little loss — BP + heart rate carry the signal.
2. Diabetes on Pima collapses without glucose; the **CDC dataset** (built glucose-free) fixes it.
3. On these small datasets, **simple models (LogReg/SVM) beat the boosters** — boosting only
   wins at the 253k-row CDC scale. The "gradient boosting wins on tabular data" effect is
   sample-size dependent.

## API behavior (Task 4)

Start: `.venv/bin/uvicorn src.api:app --port 8000`, then open `/docs` to click-test it.

| Route | Purpose |
|---|---|
| `POST /predict/{condition}/{variant}` | `condition`=diabetes\|heart, `variant`=full\|deployable |
| `…?algo=<name>` | optional — pick any of the 14 models (default = best) |
| `POST /predict/risk` | shared biomarker contract → both deployable models at once |
| `GET /models` | list every model + its scores/features |
| `GET /models/best` | best model + metrics for each condition × variant (winners only) |
| `GET /health` | liveness check |

Each request returns `{risk, at_risk, threshold, confidence, imputed_features, model_metrics}`.
`model_metrics` reports how good the serving model is (ROC-AUC, precision, recall, F1 — measured
on the test set), so the caller knows how much to trust the score. Missing inputs are
auto-imputed and reported; `confidence` drops to `low` when too much was guessed.

### Which model serves each endpoint

By default each endpoint uses the **best model** for that group (override with `?algo=<name>`
to pick any of the 14). Check live winners with `GET /models/best`.

| Endpoint | Default model | Test ROC-AUC | Fields the model uses |
|---|---|---|---|
| `/predict/diabetes/full` | Logistic Regression | 0.823 | Pima: `Glucose, Insulin, SkinThickness, BloodPressure, BMI, Age, Pregnancies, DiabetesPedigreeFunction` |
| `/predict/diabetes/deployable` | CatBoost | 0.808 | CDC: `HighBP, BMI, Age, Sex, Smoker, PhysActivity, GenHlth, DiffWalk` |
| `/predict/heart/full` | CatBoost | 0.915 | UCI: `age, trestbps, chol, thalach, oldpeak, sex, cp, fbs, restecg, exang, slope, ca, thal` |
| `/predict/heart/deployable` | Logistic Regression | 0.875 | UCI: `age, trestbps, thalach, sex, cp, exang` |
| `/predict/risk` | both deployable | — | biomarker contract (mapped below) |

Field meanings: `trestbps`=systolic BP · `thalach`=heart rate · `sex` 1=male/0=female ·
`cp`=chest-pain type (1–4) · `exang`=exercise angina (0/1) · `HighBP`=high-BP flag 0/1 ·
`Age` (diabetes)=CDC bucket 1–13 · `GenHlth`=self-rated health 1(excellent)–5(poor) ·
`Smoker`/`PhysActivity`/`DiffWalk`=0/1.

`/predict/risk` mapping (biomarker contract → model fields): for **heart** `systolic→trestbps`,
`heart_rate→thalach`, `profile.{age,sex,cp,exang}`; for **diabetes** (CDC) BP→`HighBP` (≥130/80),
`profile.age`→CDC age bucket, `profile.{bmi,sex,smoker,phys_activity,gen_health,diff_walk}`.
`hrv_sdnn` and `stress_index` are accepted but **not used** (no labels pair them with these targets).

### What to send

**On "required":** every field is optional in the schema — anything omitted is median-imputed
and listed in `imputed_features`, which lowers `confidence` (→ `"low"` once >half are missing).
So nothing is strictly required, but send the fields above for a trustworthy score. For
`/predict/risk` the `biomarkers` object must be present (its sub-fields may still be omitted).

`POST /predict/heart/deployable` — `trestbps`=systolic BP, `thalach`=heart rate, `sex` 1=male/0=female,
`cp`=chest-pain type (1–4), `exang`=exercise angina (0/1):
```json
{ "age": 60, "sex": 1, "trestbps": 145, "thalach": 150, "cp": 4, "exang": 1 }
```

`POST /predict/diabetes/deployable` — CDC glucose-free model. `HighBP`=0/1, `Age`=CDC bucket (1–13),
`GenHlth`=1–5, others 0/1 (use `/predict/risk` for friendly years/BP mapping):
```json
{ "HighBP": 1, "BMI": 31.2, "Age": 7, "Sex": 1, "Smoker": 1, "PhysActivity": 0, "GenHlth": 4, "DiffWalk": 1 }
```

`POST /predict/risk` — the integration call. `biomarkers` is required, `profile` optional.
The API maps `systolic→trestbps`, `heart_rate→thalach`, BP→`HighBP`, `age`→CDC bucket, and the
rest of `profile` to each model:
```json
{
  "biomarkers": {
    "heart_rate": 78, "hrv_sdnn": 38, "stress_index": 0.71,
    "blood_pressure": { "systolic": 142, "diastolic": 91 }
  },
  "profile": { "age": 54, "sex": 1, "bmi": 29.0, "cp": 4, "exang": 1,
               "smoker": 1, "phys_activity": 0, "gen_health": 4, "diff_walk": 1 },
  "conditions": ["diabetes", "hypertension"]
}
```
Returns `{ diabetes_risk, hypertension_risk, confidence, _detail, _full, _notes }`. The headline
scores + `_detail` are the **deployable** models (trustworthy, app-obtainable). `_full` adds the
**full-clinical** model outputs as extra data — meaningful only if you also send an optional
`clinical` block (glucose, cholesterol, oldpeak, …); without it, `_full` imputes those and reports
`confidence: low`.

### Known honesty caveats (surfaced in `/predict/risk` response `_notes`)
- `hypertension_risk` is currently served by the UCI *heart-disease* model as a proxy — a
  dedicated hypertension target exists (`framingham.prevalentHyp`) or can be read directly by
  thresholding Group 1's blood pressure.
- The heart model's `thalach` feature was trained on *exercise-max* heart rate but is fed
  Group 1's *resting* heart rate at inference.
